# SillyTavern Auto Rewrite（正文重写 · 独立版）

**当前版本：3.1.4** · RevolvinDoor fork · 原生 Swipe / RevoPhone 适配版

基于 wujimol 原作，整合 [wmdl2 的原生 Swipe PR #1](https://github.com/wujimol/SillyTavern-Auto-Rewrite/pull/1)（f7b8ddad2bda9fe5faed3a875c72bfc7165f53bc），再加入可选的 RevoPhone 联动协调。

让 SillyTavern 在回复生成后再自动（或手动）重写一轮的扩展，**不需要改酒馆本体**，官方原版酒馆直接安装就能用。

**3.1.4 修复**：正常发送用户消息时不再误取消本轮自动重写；电话等安静后台请求不会取消排队中的正文重写，也不会作为正文触发重写。自动开关仍需主动打开，开启后从下一次新正文生效。

## 为什么做这个扩展

很多时候模型第一轮直出容易写歪、台词油腻或者逻辑跟不上，但自己在聊天里手动发一句“重写”又会把废话留在记录里占上下文。

这个扩展把“重写一轮”自动化了：第一版写完后让模型审视原稿，在同一楼生成重写候选；修改意见只进入本次请求，不额外占用聊天楼层。

## 怎么工作的

点正文底部的 **「重写」**（或打开 **「自动」** 开关）后，扩展会等酒馆这一轮生成、保存和翻页完成，再调用酒馆原生 Swipe 入口：

1. 在原回复楼层直接生成一个新的 Swipe 候选，沿用酒馆的预设、世界书、输出正则、流式输出和原生生成事件。
2. 原稿按 assistant 角色、原作者或用户填写的修改意见按 user 角色，通过本次临时提示注入交给模型；不添加额外引导语、标题或包裹标记，原作者默认提示词原文不变。原用户消息及其扩展字段保持在原来的楼层。
3. 完成后直接保留宿主生成的候选，原稿继续作为该楼旧 Swipe，可通过原生翻页或快捷按钮切换。

重写流程不追加临时用户／AI 楼层，不删除临时楼层，也不搬运回复或重新拼接整条消息。扩展只为候选添加自己的版本链接与计时元数据，不复制或还原其他插件的消息字段。

## 主要功能

- **底栏操作条（与翻页胶囊同一行）**：在最新一条角色回复底部提供「重写」「查看原稿 / 返回重写版」「自动」开关和设置入口，在原稿和重写版之间切换不会重新请求模型。
- **稳定的生成状态栏**：重写期间将同一组操作固定在聊天区底部，不随同楼流式正文反复重建；预留对应空间，结束后回到正文底部。设置弹窗固定外框高度，内容内部滚动。
- **自动重写**：默认关闭；打开后每次新生成回复（包括点右箭头新抽卡）都会自动重写一轮，只翻看已有旧版本不会触发。
- **自定义修改意见**：点底栏设置图标或扩展面板里的「正文重写 · 独立版」，可以自己修改发给模型的重写要求。
- **多套修改意见预设**：内置「原作者默认」「设计工作台」，支持另存、切换、重命名与删除自定义意见；编辑内容自动保存，旧版自定义意见自动保留。
- **原生停止与防丢稿**：中途按酒馆自带的停止按钮就能取消，失败或取消后通过原生 Swipe 切回原稿，并通过宿主接口清理归属明确的本次未完成候选，不删除聊天楼层；候选归属不明确时保留记录，不猜测删除。

## 安装方法

在酒馆的 **扩展 → 安装扩展** 中直接填入仓库地址：

```text
https://github.com/RevolvinDoor/SillyTavern-Auto-Rewrite
```

或者手动下载源码，将 `index.js`、`native-swipe.js`、`reply-delivery.js`、`feedback-presets.js`、`revisions.js`、`ui.js`、`model-routing.js`、`manifest.json`、`style.css` 放到酒馆的第三方扩展目录下，刷新页面即可。

> 如果之前装过旧的定制版，建议先禁用或替换掉旧版，避免两个扩展同时触发。

## 重写模型与 API 配置

在设置里的「重写模型」卡片，选择「沿用当前 API」或酒馆连接管理器中已保存的聊天补全 API 配置，再选择或填写模型型号。型号留空时使用该配置保存的模型；两项都不指定时沿用首轮连接。可以首轮使用 low 型号，第二轮使用另一型号或另一渠道。

输入框支持酒馆已有型号、同一连接保存过的型号及手动输入。点右侧刷新，读取所选渠道的模型列表；不提供列表的渠道可以直接填写准确型号。列表按连接区分，不把其他自定义端点的列表当作当前端点可用模型。

只临时切换连接参数、模型与请求使用的密钥 ID，不切换目标配置的写作预设、提示词后处理或正则。仍使用酒馆原生生成入口；完成、报错或取消收尾后恢复首轮参数，不轮换服务器默认密钥。运行期间对设置的主动修改会保留；请勿同时用其他扩展发起依赖当前全局连接的后台生成。

支持聊天补全 API（含自定义 OpenAI 兼容、Vertex、Google、Claude 等），不支持文本补全与聊天补全之间跨类型切换。特殊请求头或自定义请求体应保存在连接配置引用的 API 预设中；切到另一自定义地址且没有对应保存数据时，不携带前一地址的请求头和请求体覆盖项。

模型与连接选择沿用现有路由实现；验证范围见下方。

## 使用注意与兼容说明

- **RevoPhone**：本 fork 与 RevoPhone 1.4.4 或更新版提供可选协作；其他插件仍遵循原生 Swipe 边界。
- **插件兼容边界**：生成过程走原生 Swipe，其他插件接收到宿主的 `MESSAGE_SWIPED`、`GENERATION_STARTED('swipe')`、`MESSAGE_RECEIVED(id, 'swipe')` 与渲染事件。不会用 `automatic_trigger` 把正文伪装成后台 normal 生成，也不人为重发消息交付事件。原生 Swipe 已有的插件限制仍然存在：例如其他插件的首稿结算、每个候选的数据恢复、仅对 normal 触发的逻辑。此扩展不改写数据库或其他插件来额外解决这些问题。
- **提示词保持范围**：默认提示词和用户保存的修改意见原文不变，原稿仍使用 assistant 角色，修改意见仍使用 user 角色。原生 Swipe 与 normal 的宿主事件、历史处理及提示注入机制有差异；特殊世界书触发、深度正则、思考签名、附件、上下文裁剪和其他插件逻辑不能据此保证与原版逐项一致。
- **生成设置**：尊重当前消息的禁止翻页、循环翻页等设置；不能生成新 Swipe 时明确提示，不临时改动宿主偏好来绕过。只对最新的单角色正文重写，不支持群聊与开场白。
- **工具调用与其他生成**：工具调用如果由宿主扩展为工具记录／后续回复，按宿主自己的流程保留，扩展不会再把这些楼层删除或拼回原楼。无法确认仍属于同楼候选时不会强行覆盖记录。其他扩展并发启动新生成时会释放本次临时提示和模型路由。
- **旧版恢复**：保留旧版临时楼层的中断恢复入口，只用于已有旧版中断记录；新版重写本身不产生这种楼层。
- **额度消耗**：每次重写会多发一次模型请求，开启自动重写时单轮会消耗两轮额度。
- **适用范围**：目前只支持单角色聊天；群聊、开场白和纯空白回复不会触发。

## 修改意见预设（3.1.3）

在重写设置中选择「修改意见预设」：编辑下方文本会自动保存到当前预设，切换后分别保留。要建立另一套，填写「新预设名称」再点「另存为」；自定义预设可以重命名或删除。内置预设也可以修改内容，恢复按钮可还原内置原文；恢复或删除前会确认。原作者默认意见原文保留，升级前保存的其他内容（包括空内容）迁入「原有修改意见」并继续选中，不会被工作台意见覆盖。

「设计工作台」参考用户本地墨月写卡工坊中的设计工作台 `2.0.1-revophone.5`，针对设计稿检查需求范围、图片依据、字段与 XML 闭合、尺寸标定和区间、能力条件以及生图栏目分离。它要求交付可直接替换的完整设计稿，不套用小说式批评、固定篇幅分析或 `<pre>/<content>` 包装；高精度模式只给简短校准摘要。它不包含整张工具卡，也不代替当前对话中的模块规则与模板，使用时仍需提供相应上下文和参考图。

正在进行的重写使用启动时的修改意见；途中切换或编辑预设只影响后续请求。模型是否完全遵从设计规则仍需结合实际输出检查。

## RevoPhone 联动（3.1.2）

两个扩展更新后自动启用联动协调，不修改酒馆本体；是否自动重写仍由「自动」开关决定。

RevoPhone **1.4.5** 配合本扩展 **3.1.4** 起，可在「设置 → 正文 → 正文自动重写」控制同一个自动开关，并进入修改意见设置；这不控制电话、Soul 私聊、朋友圈、助手或配音／配图后台请求，它们不参与重写。未安装或禁用本扩展时，该入口不可用，RevoPhone 其他功能照常。这里的开关等同于本扩展中的「自动」，没有第二份独立状态。

- 自动重写：首稿仍可阅读；手机自动联动等待本次重写完成，只按最终保留稿交付一次。等待生成／保存期间输入草稿会继续暂缓重写；关闭自动开关可立即按原稿继续联动。
- 失败或停止：通过原生 Swipe 恢复原稿后，按原稿继续；切换聊天或消息归属改变时不向新聊天交付旧结果。
- 事后手动重写：更新正文绑定状态与手机消息，不重复累计自动朋友圈、自动来电和主动联系的回复次数。已经发生的独立活动保留。
- 查看原稿／返回重写版：角色状态与正文绑定手机消息跟随当前候选。手机里已经有玩家回复的对话保留；不会因为翻页再次触发独立动作或自动生成手机照片。
- 单独使用：Auto-Rewrite 不依赖 RevoPhone。RevoPhone 没安装此 fork、此扩展已禁用、自动重写关闭且未手动重写时，继续原有流程。其他分支或旧版组合没有本次延后交付协议。

可选接口使用 `globalThis[Symbol.for('st.auto-rewrite.standalone')].replyDelivery`，版本为 `1`。消费者在接收／渲染时调用 `waitForReply(id, type)`：普通回复同步返回 `null`；明确的自动等待或正在进行的重写返回同一 Promise。Promise 在原生生成、恢复、提示清理与模型路由释放之后解析为 `{ready, count, key, index, message, swipeId, text}`。只有 `ready` 且聊天／消息／版本仍匹配时交付；`count: false` 表示事后手动重写。不要在宿主事件回调中返回或 await 该 Promise，避免阻塞后续原生事件。关闭待处理的自动重写会释放原稿；禁用运行中的重写会先完成取消清理再释放接口。

此接口只协调交付，不屏蔽、重发宿主事件，也不复制其他插件的消息字段。真实模型、真实账号和 Android 操作仍需实际使用验收。

3.1.4 同一 runtime 另提供可选 `control` v1：`getState()` 返回 `{available, auto}`，`setAuto(boolean)` 修改原有开关，`openSettings()` 打开本扩展设置，`subscribe(listener)` 返回取消订阅函数。消费者应在关闭界面时取消订阅；缺少该接口时提示更新，不直接写入其他扩展的私有设置。

## 本地验证

使用 Node.js 运行定向测试（无外部依赖）：

```sh
node tests/run-tests.mjs
```

当前 7 项预设状态测试与 34 项隔离宿主用例通过，覆盖旧意见迁移、分别保存、切换、重命名／删除、默认原文保留、实际请求意见与运行中切换，以及原有可选交付接口的自动／手动、禁用、取消、失败与上下文切换。运行器逐例使用独立 Node 进程，避开本机 Windows Node 22.19.0 在同一进程重复使用实验性 VM 模块时的进程崩溃；所有用例各执行一次，任一失败都会退出。这只影响测试运行器，不是扩展运行参数。

本次另在隔离本地 Chromium 界面中验证预设选择、另存、编辑、重命名、删除、名称转义，以及桌面和 360px 窄屏布局。该页面只挂载真实 UI 模块和模拟宿主设置，不连接实际酒馆或模型。

3.1.4 新增真实事件顺序回归（生成开始后才发用户消息）、后台请求隔离、后续用户输入取消以及共享开关测试；另有 6 项跨仓库接口组合用例，覆盖从 RevoPhone 开启自动和真实后台 `generateRaw` 路径单次请求、不生成正文或 swipe。修复前事件顺序用例复现自动请求数为 0，修复后为 1。尚未在用户的真实连接和 Android 设备中验收。

本次测试使用模拟宿主覆盖同楼 Swipe、事件与楼层数、原字段保留、旧候选重写、自动模式、停止／失败、切聊天、模型路由释放及中断恢复。PR 作者在整合前另用隔离 SillyTavern 1.18 / Chromium 153、合成聊天与模拟回复验证过非流式／流式、自动改写、停止／失败、存档重开与版本切换，并报告默认修改意见在 none 和 strict 设置下，改造前后完整 messages 相同。本次 RevoPhone 适配未复跑该浏览器环境，也未验证真实模型渠道、TauriTavern 实机或所有第三方插件组合。
